# 徐徐的 2024 年终总结

大家好，我是徐徐。今天说说 2024 年这一年，进行一个年终总结。

## 前言

还有 10 天就 2025 年了，最近刚完成了 2024 年的 OKR Review，然后对自己一年的工作做了一些梳理，想想在这里也浅浅地总结一下，当然不限于工作，希望后面每一年都可以进行一次总结。

## 关于工作

大概分为以下三块：

1. 为我之前开发的零信任桌面客户端做性能优化和体验优化以及一些工具产品
2. 常规地从 0 到 1 构建了一个后台 Web 系统
3. Web 设备指纹 SDK 以及小程序设备指纹 SDK 的探索和开发

### Electron 零信任桌面客户端相关工作

![画板](/img/notes/2024-year-end-summary/01.jpeg)

我们研发的这款产品前期比较注重能力上的建设，时间都比较仓促，要完成一些核心的 KPI，所以随着时间的推移，欠下的技术债就相对多了起来，那么就导致了一些性能上的问题和用户体验上的问题，所以今年就花了很多时间去做性能以及用户体验相关的优化。

在写 OKR 的时候，相关的指标都是定好了的。比如性能提升要多少，能耗要降低多少，客服量需要下降多少，在这个过程中我是非常能感受到一个产品要从及格到优秀是多么的不容易，关键是我们的产品经理还请产假了，最终导致的结果就是我和业务方自己写 PRD，然后完成相应的工作。

#### 说说 Electron 性能优化

![](/img/notes/2024-year-end-summary/02.png)

这里只谈谈大体的思路，具体细节由于篇幅问题就不深入了。要做桌面端的性能优化前期是需要做一些问题摸排的，需要统计端上某些方法的执行耗时以及整个应用的内存占用情况统计，如果没有这些数据，你是无法知道整个客户端在不同机器上的表现情况的，那么也就无法做出相应的调优动作。

第一步：埋点上报统计方法执行耗时和应用的内存占用情况。有了这些上报的数据之后，我们就可以看到一些方法的执行时间，然后也可以看到是在哪些时段内存占用较高，好摸排是否是后台下发策略导致的并发执行导致的问题。

第二步：优化执行耗时长的方法，减少 CPU 的突刺。

经过统计，大部分都是因为底层系统信息采集导致方法执行慢的，因为我们前期为了快很多信息采集都是用命令行实现的，里面有非常多的 Powershell 的调用，后面我们就把所有的命令行调用进行了改造，采用 rust 的方式去调用 windows 的 API 来实现，包括进程信息，软件信息以及一些常规的系统信息和硬件信息。另外通过统计发现，某些时刻客户端的 CPU 占用非常高，后面经过排查是发现很多任务并发执行导致的，特别是在整分钟的时刻，因为我们后台配置了非常多的策略动作，都是几分钟执行一次这种，当然还有秒级别的定时策略。为了缓解这个问题，后面就自己研究和实现了一整套任务队列，上线之后 CPU 的突刺明显减少。

当然在这个优化的过程中其实也让我对 Chrome Devtools 的使用更加熟练了，比如使用 Chrome Task Manager 观察实时 JS 内存使用，使用 Performance 可视化检测内存泄漏，查看内存堆快照以及进行快照对比，通过查看内存分配时间轴信息查看内存回收情况，之前这些技能都是在纯前端开发的时候使用的，但是都不太熟练，后面在 Electron 的使用中，我也用了同样的方式去调试主进程，当然主进程的调试比渲染进程的调试要稍微复杂一些，而且还有一定的局限性，很多时候代码编译过后并不能找到最终的代码块，特别是有原生模块调用的时候，所以很多时候是一步步 debugger 结合本地日志，靠着经验和直觉去发现问题，一遍遍跑内存快照，然后去找出内存快照之间的差异去发现问题。

第三步：灰度和效果回收。当你费尽力气优化后，是需要看到一些数据的，这样才能体现自己的成果，当然在优化之后不能马上直接就上线了，灰度这个过程少不了，可以佐证自己的优化是否生效，因为端上的环境的差异会比较大，如果灰度发现和自己的预期不符合，需要及时调整。我就在这个过程中去反复修改和兼容一些方法的，端上需要做好容错措施，这样才能保障稳定性。

#### 谈谈用户体验

![](/img/notes/2024-year-end-summary/03.png)

用户体验这个东西其实是比较感性的一个东西，有的人会觉得这个功能好，有的人会觉得这个功能不好。但是客诉的数量可以侧面反应出大家对这个产品的满意程度和使用方便度，当然这个指标其实是比较单一的，但是它是比较直观的。用户体验还有其他维度，比如实用性，易用性，美观性，交互流畅度之类的，我们所做的优化也都是从这些方面去出发的，比如做一些引导，对界面做一些改版，加上一些动画，然后再做一些实用性的工具箱，都可以提升用户体验。

在做用户体验的时候其实是需要专业的 UI 设计师的，但是对内的产品，UI 设计基本都是最低优先级的，再加上没有产品经理，但是有的优化又必须要做，只能自己上了。但是研发到产品思维的转变这一块并不是那么容易，所以很多时候去做一个功能的时候如果只局限于技术的角度，做出来后可能并不会受到人们的青睐，不过好在自己是前端，所以对一些审美和交互我还是有一些自己的 Sense，大体上可以自己写 PRD 然后评审需求后听取大家的意见再进行修改，大体也能做到个七七八八。

### 设备指纹 SDK 相关工作

![](/img/notes/2024-year-end-summary/04.png)

这一块之前的确没有怎么接触过，以前也都只有知道原生应用有设备指纹应用的场景，后面了解到在 Web 端和小程序也有相应的应用场景。正好部门有些地方的策略可能需要用到这一块的能力，然后就研究起来了。不过上半年没有怎么投入，下半年才开始投入的，了解了相关原理发现其实端上能做的非常有限。客户端最主要的能力就是采集各种信息然后形成各种特征参数，最后喂给算法形成特定的设备指纹哈希。

在这个期间就是了解了各种前端的 API，最主要就是 navigator 上的各种属性，最后整合了一些声音指纹，canvas 指纹，字体指纹，webgl 指纹等，然后获取一些常规的硬件信息，最后加密上报给服务端，然后前期做一些简单的数据分析，看看纯前端方案下的设备指纹膨胀率之类的。

这个东西说实话，用处真的不是很大，在一些风控场景下只能进行辅助分析，加上没有确定的唯一标识（当然可以本地存一个 UUID），即使有一些特征了，最后给算法去计算去训练能产生的收益并不大。因为大部分的策略依赖端上的东西大概还是像应用是否多开，手机是否 root，是否为模拟器之类等一些比较硬核的特征，因为大部分情况下还是在 APP 壳子里面玩，端外 H5 的场景越来越少了。

然后就是小程序的设备指纹，这一块其实也是非常有局限性的，采集的信息大多还是有限，要么就是有的采集需要用户各种授权，作为这种 SDK 你是不能影响业务的核心流程的，很多东西也不是采集得越多就越好，涉及到用户信息相关的安全条例，搞不好整个小程序都被下架，得不偿失，所以只能采集一些比较基本的设备信息，而且还要做一些兜底，各种判断相关方法是不是可以使用，因为小程序的基础版本在很多机器上是有差异性的，那么相关的 API 也是有差异的，最后就变成了各种方法的兼容。

设备指纹最为核心的能力其实还是算法层面的能力，经过模型分析去做相应的指纹生成，端上就是保证采集的信息无误就好，剩下的就交给算法吧。

### 旅行

![](/img/notes/2024-year-end-summary/17.jpeg)

旅行的话，印象最为深刻的就是和几个朋友去了趟川西，来了一场自驾旅游。感受最深的就是每到一个地方大家都是「哇」声一片，真的非常洗眼睛。另外就是你一天可以感受四个季节，感受自然的变化。当然在 318 国道上开车驰骋的感觉也是非常舒服的，景色各不相同，有大河，有草原，有山川，有云海，有雪山，正应了那句话：此生必驾 318。

另外就是还去了景德镇、福州、平潭、缙云。各有特色，各有风情，各有美食，各有风景。

![](/img/notes/2024-year-end-summary/18.jpeg)

进入景德镇之后你会被各种瓷器吸引，看得让人眼花缭乱，感觉就像进入了陶瓷窝一样，除了瓷器还是瓷器，每个店都有自己的特色，品种也各不相同，如果你是手作或者瓷器爱好者，这个地方可以让你玩上好几天。还有就是景德镇有几家大排档可以去吃一下，味道相当霸道，作为一个重庆人都觉得那个辣度很辣，怕辣的最好不要尝试，怕你流泪。

![](/img/notes/2024-year-end-summary/19.jpeg)

福州给人的感觉是比较有烟火气息的，旅游业不算太发达，带有小资气息，富有文化底蕴。当然肯定要去打卡几个著名的景点了，不然也枉来一趟，随便逛逛，拿着相机到处拍一拍就非常惬意。

![](/img/notes/2024-year-end-summary/20.jpeg)

平潭是非常值得去的一个地方，可以租个电动车，然后环岛骑行，满眼都是蔚蓝的天空和碧绿的海水，如果遇到好看的景色可以随处停留拍照打卡，寻找一个海湾和三五好友坐下听海浪的声音，喝一杯略带咸味的手作饮料，静静地等待日落的降临。

![](/img/notes/2024-year-end-summary/21.jpeg)

缙云跟预期的有所差距，人多，风景不多，地方也小。要去最好是抽空闲的周末，节假日不要去。之所以火爆是因为有几部电视剧是在那个地方取景的，所以很多人都会去打卡。江浙沪周边两日游可以选择这个地方，也有比较容易出片的地方，可以感受山水间的气息。

### 摄影

![](/img/notes/2024-year-end-summary/22.jpeg)

摄影这个爱好我已经保持了很久了，从大学就开始玩，但是设备一直没有怎么更新换代，一台狗头相机拍了六七年，镜头也没有买新的，不过这都不影响我的爱好，因为我觉得完全够用了，不管是人像还是风景都可以适应。之前我拍摄的照片都是发微博，后面开通了微信公众号，就专门建了一个专栏来更新我的摄影记录，然后发了一些存量的照片，有些照片太久远了，实在不想去翻，就看心情，偶尔看到哪一组比较好的我就挑出来发布到公众号上。我周末也会偶尔带上相机到处转悠，然后记录一些街景，如果出去玩我也会带上相机去记录，不得不说好看的照片会让人心情愉悦，因为每一张照片都是独一无二的，它会让你想起当时的一些情景，这也是我为什么喜欢摄影的原因。

### 骑行

![](/img/notes/2024-year-end-summary/23.jpeg)

骑行算是今年重拾起来的一个运动。大学的时候就玩骑行，但是那时候玩的是山地车，不是公路车。十一过后我决定试试公路车，后面就开始了骑行运动，不冷的时候每周都会骑，两个月时间大概骑行了 600 公里，当然其中有 300 公里是环太湖获得的里程。从大学过后基本就没有一天骑行超过 100 公里的经历了，但是今年环太湖真的打破了自己的记录，骑完之后感觉自己无所不能。骑行可以让人获得很多很多的多巴胺，让人非常的高兴和兴奋，只要不太过剧烈，对人的身体是非常有好处的。

### 羽毛球

![](/img/notes/2024-year-end-summary/24.jpeg)

对于羽毛球，只能算得上初级选手。之前还专门上了私教课，可惜的是刚练到走位就退课了。对于久坐办公室的人，这项运动也非常有好处的，所以今年我也打了很多场羽毛球。基本每周都会打一次，不管是和部门的同事还是公司的同事，反正保持每周一次的频率。和部门的同事打比较悠闲一些，和公司的同事打就是真正的锻炼，会增长自己的技术，因为公司里面还是有很多高手，我也是从一个菜鸟慢慢变成了初级选手，刚开始的时候很多规则都不懂，后面打着打着就感觉自己不管是反应还是走位都比刚开始玩的时候进步了不少，同事都说比之前好多了。

## 结语

回看这一年，时光飞逝。总结一下之后感觉今年好像还是非常丰富多姿的一年呢，文字记录下来之后会让人的思路更加清晰，也会反思自己这一年的一些事情，我自己感觉是非常不错的。

把一年浓缩在 6000 字的文章中就感觉像把自己的一年酿成了一瓶酒，然后写上了年份，可能某一天打开重读的时候还能感受到岁月沉淀的醇香。

每个人都有自己的独特的生活轨迹和思考方式，这篇总结只是我个人的总结和观点，各位看官不喜勿喷。感谢一路相伴的朋友们，愿我们都能在新的年岁里找到属于自己的精彩。
